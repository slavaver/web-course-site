# Вычисляемые значения и управление эффектами

Это второй этап работы над нашей UI-библиотекой. В нем вы расширите механизм сингалов.

**Цель:** научиться управлять зависимостями между реактивными данными, создавать вычисляемые значения и контролировать выполнение реактивных эффектов с использованием TypeScript.

## Динамические зависимости

Набор используемых сигналов в эффекте может изменяться. Например, есть три сигнала: один определяет режим работы программы, второй и третий содержат некоторые значения. Эффект в зависимости от выбранного режима читает либо второй, либо третий сигнал. Когда режим меняется, эффект выполняется повторно и начинает использовать другой сигнал и теперь изменение неиспользуемого сигнала не должно приводить к повторному выполнению эффекта.

Таким образом, набор зависимостей эффекта определяется заново при каждом выполнении. Для реализации такого поведения необходимо обеспечить следующие правила:

- Перед повторным выполнением эффекта его старые зависимости должны быть удалены.
- Во время выполнения должны регистрироваться новые зависимости.
- После завершения эффекта он должен зависеть только от тех сигналов, которые действительно прочитал при последнем выполнении.
- Если эффект несколько раз прочитал один и тот же сигнал, зависимость должна регистрироваться только один раз.

## Управление временем жизни эффектов

### Остановка

Эффекты могут создаваться для выполнения временных задач. Например, эффект может следить за изменениями данных, пока существует определенный компонент интерфейса. После удаления компонента такой эффект больше не нужен. Поэтому требуется механизм остановки эффекта. Для этого при создании эффекта нужно получить средство управления его временем жизни. Вызов этого средства должен полностью отключать эффект от реактивной системы.

После остановки эффекта:

- Он больше не должен запускаться при изменении сигналов.
- Все его зависимости должны быть удалены.
- Повторный запуск остановленного эффекта не должен происходить.
- Очистка ресурсов, связанных с эффектом, должна быть выполнена.

### Очистка

Эффект реагирует на изменение некоторого значения и при каждом выполнении создает внешний ресурс (таймеры, подписки на события, сетевые запросы). Перед следующим выполнением предыдущий ресурс должен быть освобожден. Если эффект остановлен, ресурс также должен быть освобожден, но повторного создания уже не произойдет.

Чтобы это реализовать требуется механизм регистрации функции очистки эффекта. Такая функция предназначена для освобождения ресурсов, созданных во время предыдущего выполнения. Функция очистки должна вызываться перед следующим выполнением эффекта, а также при его окончательной остановке.

## Вычисляемые значения (Computed)

В реактивных программах часто требуется получать новые значения, которые зависят от других реактивных данных. Например, приложение хранит цену и количество товаров. Общая стоимость зависит от обоих значений. Если цена или количество изменились, общая стоимость должна автоматически пересчитаться. Для таких ситуаций необходимо реализовать механизм вычисляемых значений - `computed`. Вычисляемые значения предназначены именно для получения производных данных. Они не должны использоваться для выполнения побочных действий, например изменения DOM или отправки запросов.

Вычисляемое значение должно обладать следующими свойствами:

- Создаваться на основе функции, вычисляющей результат, т.е. возвращающей какое-либо значение.
- Автоматически определять используемые сигналы.
- Пересчитываться при изменении своих зависимостей.
- Кэшировать результат вычисления.
- Само выступать реактивным источником данных для других вычисляемых значений и эффектов.

Важная особенность вычисляемого значения заключается в том, что оно не должно пересчитываться при каждом обращении к нему. Если исходные данные не изменились, необходимо возвращать ранее полученный результат.

### Примеры

Есть вычисляемое значение, которое складывает два сигнала. После первого обращения результат вычисляется. Если исходные сигналы не менялись, повторное обращение должно вернуть сохраненный результат без нового выполнения вычислительной функции.

Если один из исходных сигналов изменился, вычисляемое значение должно стать неактуальным. При следующем обращении оно должно пересчитаться с использованием новых данных.

Если эффект читает вычисляемое значение, изменение исходного сигнала должно в конечном итоге привести к повторному выполнению эффекта. При этом эффект должен получать актуальный результат вычисления.

Допускается создание вычисляемого значения на основе другого вычисляемого значения. Например, одно значение определяет стоимость товаров, а другое - стоимость с учетом скидки.

При изменении исходных сигналов вся цепочка должна корректно обновляться. Необходимо исключить ситуации, когда эффект получает устаревший результат промежуточного вычисления.

## Планирование и пакетирование обновлений

В первой лабораторной работе зависимый эффект выполняется непосредственно при изменении сигнала. В этом есть определенная проблема, когда, например, есть два сигнала, содержащих координаты некоторой точки, и эффект, который использует оба значения для отрисовки этой точки. И если сначала изменить первую координату, а затем вторую, эффект выполнится дважды. При этом промежуточное выполнение использует обновленную первую координату и старую вторую.

Получается, что при изменении нескольких сигналов подряд это может приводить к лишним повторным вычислениям. Для решения этой проблемы требуется планировщик реактивных эффектов.

Планировщик должен:

- Помещать эффекты, требующие выполнения, в очередь.
- Не допускать повторного добавления одного эффекта в очередь.
- Выполнять ожидающие эффекты после завершения текущей синхронной операции.
- Обеспечивать предсказуемое завершение обработки очереди.

Для управления группой изменений может использоваться механизм пакетирования `batch`. Пакетирование позволяет выполнить несколько изменений реактивных данных, отложив выполнение зависимых эффектов до завершения всей группы операций.

Пример ожидаемого поведения:

1. Есть два сигнала, от которых зависит один эффект.
2. Начинается пакет изменений.
3. Первый сигнал получает новое значение.
4. Второй сигнал также получает новое значение.
5. До завершения пакета эффект не выполняется.
6. После завершения пакета эффект запускается один раз и получает оба новых значения.

Механизм `nextTick` позволяет дождаться завершения запланированных реактивных обновлений. Если после изменения сигнала требуется проверить результат работы эффекта, тест должен иметь возможность дождаться завершения очереди и только после этого проверять результат.

В этой работе не требуются приоритеты эффектов, несколько очередей обновлений или сложная система расписания. Несколько изменений, сделанных в рамках одной синхронной операции или одного пакета, не должны приводить к многократному выполнению одного и того же эффекта. После обработки очереди все эффекты должны работать с актуальными значениями сигналов.

## Практика

Расширьте сигнал и эффект, реализованные в первой лабораторной работе.

### Динамические зависимости

Доработайте механизм выполнения эффектов так, чтобы зависимости автоматически обновлялись при каждом запуске.

Необходимо обеспечить:

- Удаление старых зависимостей перед повторным выполнением.
- Сбор нового набора зависимостей.
- Отсутствие повторных регистраций одного эффекта на один сигнал.
- Корректную работу условных зависимостей.

### Остановка эффектов и очистка

Добавьте механизм остановки эффектов и освобождения связанных с ними ресурсов.

Необходимо предусмотреть:

- Регистрацию функции очистки.
- Получение средства остановки эффекта.
- Удаление всех зависимостей при остановке.
- Выполнение очистки перед повторным запуском.
- Выполнение очистки при окончательной остановке.
-

Если эффект уже поставлен в очередь, а затем остановлен, он не должен выполниться. Это хороший тест на согласованность механизмов.

### Вычисляемые значения

Реализуйте механизм `computed`, позволяющий создавать реактивные значения на основе других реактивных данных.

Необходимо обеспечить:

- Автоматическую регистрацию зависимостей.
- Кэширование результата.
- Сброс актуальности результата при изменении зависимостей.
- Срабатывание при каждом чтении.
- Возможность использования computed внутри других computed и эффектов.

### Планировщик и пакетирование

Реализуйте очередь выполнения эффектов и механизм пакетирования изменений.

Необходимо обеспечить:

- Постановку эффектов в очередь.
- Исключение дублирующихся эффектов в очереди.
- Выполнение очереди после завершения текущей синхронной операции.
- Пакетирование нескольких изменений через `batch`.
- Возможность дождаться завершения очереди через `nextTick`.

### Порядок выполнения

Определить и уточнить интерфейс эффектов и сигналов и сохранить совместимость с основными возможностями первой лабораторной работы.

Использовать подход TDD при написании тестов, проверяющих корректность поведения и реализации. Особое внимание уделить тестированию порядка выполнения эффектов, изменению зависимостей и очистке ресурсов.

1. Доработать механизм эффектов для корректного обновления зависимостей при каждом выполнении.
2. Реализовать механизм остановки эффектов.
3. Добавить регистрацию и выполнение функций очистки.
4. Реализовать вычисляемые значения с кэшированием и автоматическим отслеживанием зависимостей.
5. Проверить работу цепочек вычисляемых значений.
6. Реализовать очередь выполнения эффектов.
7. Добавить механизм пакетирования изменений.
8. Реализовать ожидание завершения запланированных обновлений.
9. Проверить код на замечания от статического анализатора кода (линтера).
