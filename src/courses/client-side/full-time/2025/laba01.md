# Знакомство с реактивностью. Реализация механизма сигналов

Работа является первым этапом разработки собственной небольшой реактивной UI-библиотеки. Реализованный механизм сигналов будет использвоаться в последующих лабораторных работах.

**Цель:** Познакомиться с принципами реактивного программирования и реализовать базовый механизм реактивного состояния, основанный на сигналах (_Signal_) и эффектах (_Effect_) с использованием Typescript.

## Императивный и реактивный подходы

В обычной императивной программе разработчик самостоятельно определяет, когда и какие действия необходимо выполнить после изменения данных. Например, если программа хранит значение счетчика, то после его изменения разработчик должен самостоятельно обновить все места интерфейса, в которых это значение отображается.

При увеличении количества зависимостей такая организация программы становится неудобной: разработчику приходится помнить, какие части программы зависят от конкретных данных, и вручную поддерживать их согласованность.

Реактивный подход предполагает, что программа может автоматически реагировать на изменение данных. Вместо явного вызова всех необходимых операций разработчик описывает зависимость некоторого действия от данных. Реактивная система самостоятельно определяет, когда это действие необходимо выполнить.

## Понятие сигнала

Сигнал (Signal) - это объект, который хранит некоторое значение и предоставляет интерфейс для чтения и изменения этого значения.

В простейшем варианте сигнал должен поддерживать две основные операции:

- Получение текущего значения.
- Запись нового значения.

При чтении сигнала во время выполнения реактивного эффекта система должна определить, что текущий эффект зависит от этого сигнала. Таким образом, само чтение значения при создании эффекта становится операцией регистрации зависимости.

При изменении значения сигнал должен уведомить все эффекты, которые ранее читали его значение.

Сигналу не требуется знать назначение этих эффектов. Он хранит значение и обеспечивает связь с системой реактивных зависимостей.

## Понятие реактивного эффекта

Реактивный эффект (Effect) - это функция, которая автоматически выполняется при создании и повторно запускается при изменении используемых ею реактивных данных.

В простейшей модели эффект представляет собой функцию, которая выполняет некоторую операцию, например выводит текущее значение сигнала в консоль; записывает новое значение в журнал; выполняет некоторое вычисление; обновляет внешнее представление данных.

Разработчик не должен вручную подписывать эффект на каждый используемый сигнал. Регистрация зависимостей происходит неявно - в момент чтения сигнала при создании эффекта.

## Практика

Необходимо реализовать механизм реактивного состояния, состоящий из сигнала и механизма наблюдения за его изменениями.

Работать необходимо в репозитории [задания TS на Gitverse](https://gitverse.ru/smartclass?invite=e8b1feef-de7c-11f1-9885-0ada33e6cf35) на ветке main. Окружение для работы должно быть как в первой практической работе (линтер, форматер, тест-фреймворк).

### Сигнал

Разработайте объект `Signal`, предназначенный для хранения реактивного значения.

Она должна предоставлять следующие возможности:

- Создание сигнала с начальным значением.
- Получение текущего значения.
- Запись нового значения вместо старого.
- Оповещение зарегистрированных обработчиков при изменении значения.

Сигнал должен быть универсальным по типу хранимых данных. Например, он должен позволять хранить числа, строки, логические значения и объекты.

При изменении значения старое значение должно заменяться новым. Сигнал не должен автоматически сохранять историю предыдущих значений.

Ожидаемое поведение: если сигнал изначально хранит одно значение, а затем получает новое, последующее чтение должно возвращать именно новое значение.

### Реализация механизма наблюдения за изменениями

Необходимо предусмотреть возможность регистрации обработчиков, которые будут вызываться при изменении значения сигнала.

Для этого следует определить механизм подписки на изменения.

Обработчик должен получать информацию о произошедшем изменении. Как минимум, должна быть доступна возможность узнать новое значение. Дополнительно можно передавать предыдущее значение.

Ожидаемое поведение:

- После регистрации обработчика он начинает получать уведомления об изменениях.
- При записи нового значения зарегистрированные обработчики вызываются.
- Несколько обработчиков могут независимо наблюдать за одним сигналом.

### Эффекты

Разработайте объект `Effect`, принимающий функцию, которая должна выполняться реактивно.

Эффект должен:

- Выполняться сразу после создания.
- Устанавливать себя в качестве текущего активного эффекта на время выполнения.
- Автоматически собирать зависимости от сигналов, которые читает.
- Повторно выполняться при изменении любого из используемых сигналов.
- Восстанавливать контекст выполнения после завершения.

Необходимо предусмотреть возможность повторного запуска эффекта без создания новых экземпляров эффекта. При повторном выполнении эффект должен корректно обновлять информацию о своих зависимостях.

И добавить защиту от повторной регистрации одного и того же эффекта на один сигнал. Иначе эффект, который читает сигнал несколько раз, может запускаться несколько раз при одной записи.

Разработчик описывает действие один раз, а система самостоятельно определяет, когда его необходимо повторить.

## Рекомендуемый порядок выполнения

Определить интерфейс публичного API сигнала и эффекта.

Использовать подход TDD при написании тестов, проверяющих корректность поведения и реализации. Дополнительно необходимо проверить, что обычное чтение сигнала вне эффекта не приводит к регистрации фиктивной зависимости.

1. Реализовать хранение начального значения и операции чтения.
1. Реализовать замену текущего значения новым.
1. Добавить механизм регистрации обработчиков изменений.
1. Проверить код на замечания от статического анализатора кода (линтера).
